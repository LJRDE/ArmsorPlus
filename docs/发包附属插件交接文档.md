# FakePlayer 附属插件 — 交接文档

> 目标读者：接手"自写 FakePlayer"的另一个 AI。
> 本插件是一个**独立的 Bukkit 附属插件**，提供一个**像原版生物一样的 `FakePlayer` 类**：
> spawn 出来就自己管渲染（带皮肤的玩家模型）、自己寻路追击、自己能被打、能死。
> 主插件 `ArmsorPlus` 检测到本插件时，`new` 一个 `FakePlayer` 并挂几个回调（掉落/血条），没装时退化为隐形盔甲架（已有兜底）。

## 1. 背景与目标

主插件 `ArmsorPlus`（Paper/Purpur 1.21.11）有一个"玩家模型 Boss"系统，现在的实现是把职责摊在三个类里：

- `ModelBoss`：隐形盔甲架（真实物理本体，命中盒/击退/血量/追击）。
- `BossRenderer`：PacketEvents 发包渲染假玩家 + 攻击拦截 + tick 同步。
- `PlayerBoss` / `VillageCaptain`：AI 技能循环、召唤、掉落。

问题：发包依赖 PacketEvents（GPL、外部 jar），且逻辑摊得散、主插件臃肿。

**目标**：把"生物"这一层抽成一个**独立的 `FakePlayer` 类**（放附属插件），它像原版生物一样自包含——你给它位置/皮肤/血量，它自己生成物理体、自己渲染皮肤、自己寻路追击、自己结算受伤与死亡。主插件只负责游戏设计（召唤、技能、掉落）。

### 关键约束（必须理解）

- **玩家皮肤只能用发包渲染**。原版协议没有"自定义皮肤生物"这种实体类型，所以"像原版生物"是 **API/生命周期层面**的像（spawn/移动/受伤/死亡这些接口像生物），底层永远是"真实物理体 + 发包皮肤"。
- 物理体定为**隐形盔甲架**（轻量、可控、纯 Bukkit API），寻路是**自写**的沿墙滑动 + 跳跃翻越（不做完整 A*）。

### 职责划分

| 责任 | 归属 |
|---|---|
| 物理本体（隐形盔甲架） | FakePlayer 自己 spawn |
| 皮肤渲染（发包） | FakePlayer 自己 |
| 位置/朝向同步（每 tick 读盔甲架） | FakePlayer 自己 |
| 攻击包拦截 + 受伤结算 | FakePlayer 自己 |
| 追击寻路（绕墙/跳跃） | FakePlayer 自己 |
| 血量 / 死亡 | FakePlayer 自己 |
| 皮肤数据（value+signature） | 主插件获取，构造时传入 |
| AI 技能（影遁/幻影斩等） | 主插件（通过回调 + FakePlayer 的 swing/teleport） |
| 掉落 / 血条 / 菜单 | 主插件（通过 onDeath/onDamage 回调） |

## 2. 整体架构

```
ArmsorPlus (主插件, depend ArmsorPlusFakePlayer 拿接口)
    │  onEnable 查 ServicesManager 是否有 FakePlayerFactory
    │
    ├─ 有附属插件 ──► factory.create(options) → FakePlayer
    │                  options 携带: 位置/皮肤/血量/名字 + onAttack/onDamage/onDeath 回调
    │
    │                  FakePlayer(附属插件内部) 自己:
    │                    · spawn 隐形盔甲架(物理体)
    │                    · 发包渲染皮肤玩家模型
    │                    · 每 2 tick 同步模型到盔甲架位置
    │                    · netty 拦截攻击包 + 盔甲架命中盒 → 统一结算受伤
    │                    · 每 tick 朝 setTarget 追击(绕墙/跳跃)
    │
    │                  主插件只调: setTarget(追击) swing()/hurt()(动画) teleport()(技能) remove()(死亡)
    │
    └─ 无附属插件 ──► 不创建 FakePlayer，Boss 退化为隐形盔甲架(主插件旧兜底)
```

- **附属插件（ArmsorPlusFakePlayer）**：接口 + 实现一体（`FakePlayer` / `FakePlayerFactory` / `FakePlayerOptions` 与实现同在一个 jar）。主插件/第三方运行时 `depend` 它，保证拿到**同一个 Class 实例**（ServicesManager 服务注册与查找才匹配）。它实现接口并注册 factory 到 Bukkit ServicesManager。
- **主插件是调用方**：负责收集皮肤、写技能、挂掉落回调，通过 ServicesManager 拿工厂。
- 主插件编译期 `compileOnly` 依赖附属插件 jar（拿接口 class 引用）。

## 3. 接口契约（ArmsorPlusFakePlayer 定义并实现）

接口定义在**附属插件** `ArmsorPlusFakePlayer` 中，与实现同一个 jar（包名 `Dim_LJR.armsorPlus.Boss` 不变）：

```java
import org.bukkit.Location;
import org.bukkit.World;
import org.bukkit.entity.ArmorStand;
import org.bukkit.entity.Player;
import java.util.function.BiConsumer;
import java.util.function.Consumer;

// 生物句柄：一个活跃的 FakePlayer。位置/受伤/寻路由附属插件自己驱动。
public interface FakePlayer {
    void remove();                         // 死亡/消失: 清实体+发包+取消任务+卸netty处理器
    boolean isAlive();                     // 血量 > 0
    boolean isValid();                     // 物理本体实体仍存在(可能已空血但未清理)

    ArmorStand getBody();                  // 物理本体(盔甲架), 主插件读位置/设旋转/BossMenu追踪用
    Location getLocation();

    void setTarget(Player target);         // 设追击目标; 内部每tick chase(绕墙/跳跃), null=原地待命
    void teleport(Location loc);           // 技能瞬移(本体+视觉一起)
    void rotateTo(Player target);          // 面向目标(攻击前保证挥砍方向与朝向一致)

    void swing();                          // 挥手动画(主手)
    void hurt();                           // 受击动画(红闪)

    double getHealth();
    double getMaxHealth();
    void applyDamage(Player attacker, double amount, boolean melee); // 手动扣血(攻击包拦截兜底用; melee=true 顺带近战击退)

    void spawnTo(Player p);                // 后加入/换世界的玩家单独补发模型
    void despawnFrom(Player p);            // 对单个玩家移除模型

    // 回调注册(主插件挂游戏逻辑)
    void setOnAttack(Consumer<Player> cb);       // 玩家挥砍命中(拦截后主线程回调), 主插件算伤害并调 applyDamage()
    void setOnDamage(BiConsumer<Player, Double> cb); // (attacker, 剩余血量) 主插件同步血条/menu
    void setOnDeath(Consumer<Player> cb);         // killer → 主插件掉落+清理
}

// 工厂: 附属插件实现并注册到 ServicesManager
public interface FakePlayerFactory {
    FakePlayer create(FakePlayerOptions opt); // 失败返回 null
}

// 创建配置(主插件在召唤 Boss 时构造)
public class FakePlayerOptions {
    public final World world;
    public final Location spawnLocation; // 初始位置+朝向
    public final double maxHealth;
    public final String bossName;        // 英文名(合法 Minecraft 用户名, 用于 PlayerInfo)
    public final String displayName;     // 显示名(含 § 颜色码)
    public final String skinValue;       // textures 的 value(base64), 可为空
    public final String skinSignature;   // textures 的 signature, 可为空
    // 构造器从略
}
```

### 服务注册 / 发现

- 附属插件 `onEnable`：
  ```java
  getServer().getServicesManager().register(
      FakePlayerFactory.class, new MyFactory(), this, ServicePriority.Normal);
  ```
- 主插件 `onEnable`：
  ```java
  RegisteredServiceProvider<FakePlayerFactory> rsp =
      getServer().getServicesManager().getRegistration(FakePlayerFactory.class);
  FakePlayerFactory factory = rsp == null ? null : rsp.getProvider();
  ```

### 主插件调用流程（召唤影武者为例）

```java
// 1. 拿皮肤 value/signature(主插件已有逻辑)
// 2. new FakePlayerOptions(...) 填位置/皮肤/血量/名字
// 3. FakePlayer fp = factory.create(opt);
// 4. fp.setOnAttack(player -> fp.applyDamage(player, computeDamage(player), true));
//    fp.setOnDeath(killer -> { /* 掉落 IllusionerScrap/MagicBall + 发公告 */ });
//    fp.setOnDamage((a, hp) -> { /* 同步 BossMenu 血条 */ });
// 5. AI 任务里每 tick: fp.setTarget(findNearestPlayer());  + 技能循环(影遁/幻影斩)
```

> 关键：`FakePlayer` 负责"被追目标 + 移动 + 受伤 + 死亡"，主插件负责"选目标 + 打人技能 + 掉落"。`setTarget` 只给目标，寻路是 FakePlayer 内部的事。

## 4. 皮肤数据流

皮肤数据（textures 的 `value` + `signature`）由**主插件负责获取**，通过 `FakePlayerOptions` 传给附属插件。附属插件**不需要**读主插件 config、不需要拉 Mojang、不需要处理皮肤来源。

主插件获取皮肤的优先级（已实现，保留在主插件）：

1. 影武者（ShadowWarrior）：
   - config `BossSkinValue`（+ `BossSkinSignature`）烘焙值，优先
   - Mojang 在线拉取 `BossSkinPlayerName`（默认 `Village_master`，缓存 60s）
   - `SkinServer` 的 data-url 兜底
   - 召唤者玩家的 Paper profile textures
2. 村民队长（VillageCaptain）：
   - config `CaptainSkinValue`（+ `CaptainSkinSignature`）

附属插件收到的就是**两个字符串**：`skinValue`、`skinSignature`（可空）。发包时原样塞进 `GameProfile` 的 `textures` 属性即可。

## 5. FakePlayer 内部实现（核心）

> 本节是重点。附属插件要把主插件现在的 `ModelBoss`（本体/血量/追击）+ `BossRenderer`（发包/拦截/同步）**合并通用化**成一个 `FakePlayer` 类。以下协议细节来自主插件**已经踩过坑验证正确**的参考实现，务必逐条遵守，否则客户端会**静默不显示或直接踢人**。

参考源码（务必通读）：
- `src/main/java/Dim_LJR/armsorPlus/Boss/PacketFakePlayer.java`：PacketEvents 版发包参考（协议细节全部来自这里，含踩坑注释）。
- `src/main/java/Dim_LJR/armsorPlus/Boss/BossRenderer.java`：发包攻击拦截 + tick 同步。
- `src/main/java/Dim_LJR/armsorPlus/Boss/BossSkin.java`：皮肤 value+signature 构建（含 Mojang 在线拉取缓存）。
- `src/main/java/Dim_LJR/armsorPlus/Boss/ModelBoss.java`：盔甲架本体 + 血量 + 追击（`chase()` 已含沿墙滑动+跳跃避障，已 `implements FakePlayer`）。

### 5.1 发包通道（反射）

运行时类名是 **Mojang 映射**（Paper/Purpur 1.17+ 统一，reflection-rewriter 重写后）：

```java
// 反射等价于：
// ((org.bukkit.craftbukkit.entity.CraftPlayer) player).getHandle().connection.send(packet)
Class<?> craftPlayer = Class.forName("org.bukkit.craftbukkit.entity.CraftPlayer");
Object handle = craftPlayer.getMethod("getHandle").invoke(player);          // → net.minecraft.server.level.ServerPlayer
Field connField = handle.getClass().getField("connection");                 // → ServerGamePacketListenerImpl
Object connection = connField.get(handle);
if (connection != null) {
    connection.getClass().getMethod("send", PacketBaseClass).invoke(connection, packet);
}
```

- `ServerPlayer.connection` 字段名是 `connection`，有 `send(Packet)` 方法；可能为 **null**（未完全登录），调用前判空。
- 发包遍历世界内玩家（`world.getPlayers().forEach(...)`）。

### 5.2 要发的包（Mojang 映射类名）

|---|---|

| 生成实体 | `ClientboundAddEntityPacket`（**不是 AddPlayer！**） |

| 头部朝向 | `ClientboundRotateHeadPacket` |
| 动画（挥手/受击） | `ClientboundAnimatePacket` |
| 移除实体 | `ClientboundRemoveEntitiesPacket` |
| 移除玩家信息 | `ClientboundPlayerInfoRemovePacket` |

### 5.3 生成假玩家（spawn 的完整包序列）

顺序严格：

1. **PlayerInfoUpdate(ADD_PLAYER)** — 加进玩家列表，皮肤写这里。
2. **AddEntity（实体类型 = player）** — 生成玩家实体。
3. **SetEntityData** — 元数据（名称、名称可见、无重力、皮肤层）。
4. **SetEquipment** — 主手钻石剑。

#### 5.3.1 PlayerInfoUpdate 的严格编码（最重要的坑）

1.21.9+ 的 `PlayerInfoUpdate` 改为 **"每字段一个 Action"**：`ADD_PLAYER` 只写 `profile`（name + textures），其余字段（gameMode/listed/latency/displayName/showHat/listOrder/chatSession）都是独立 Action。

**写成旧版合并格式（把 gameMode 等塞进 ADD_PLAYER），客户端会抛 `IOException("Packet was larger than I expected")` 并断开。**

ADD_PLAYER 条目编码必须是：
```
writeEnumSet(actions=[ADD_PLAYER])
writeVarInt(条目数=1)
writeUUID(uuid)
writeString(profile.name, 16)
writeVarInt(textures 属性数)
对每个 textures 属性:
    writeString(name)      // "textures"
    writeString(value)     // skinValue
    writeBoolean(signature != null)
    if (signature != null) writeString(signature)
```

只写这些，**不要写任何多余字段**。

#### 5.3.2 AddEntity（不是 SpawnPlayer）

1.21.2+ 移除了独立 `SpawnPlayer` 包，玩家必须用**通用 AddEntity**（实体类型 = player）生成。旧的 SpawnPlayer 包会被客户端忽略 → 实体不生成 → 隐形。

关键字段：`entityId`、`uuid`、`entityType = player`、`x/y/z`、`yaw`、`pitch`、`headYaw`、`velocity`。

#### 5.3.3 SetEntityData 的元数据（索引陷阱）

`AddEntity` 不含元数据，必须单独发 `ClientboundSetEntityDataPacket`。玩家元数据索引：

| 索引 | 类型 | 值 | 说明 |
|---|---|---|---|
| 2 | OPTIONAL_ADV_COMPONENT | displayName | 自定义名称 |
| 3 | BOOLEAN | true | 名称可见 |
| 5 | BOOLEAN | true | 无重力 |
| 16 | BYTE | `0x7F` | 皮肤层全开 |

**警告**：索引 15 是 `DATA_PLAYER_MAIN_HAND`（`HumanoidArm` 枚举，不是 BYTE），曾因用 BYTE 写索引 15 被踢。**不要碰索引 15。**

### 5.4 位置同步（附属自己每 2 tick 做）

- **相对移动**：`ClientboundMoveEntityPacket`（PosRot）+ `ClientboundRotateHeadPacket`。
  - 位移任一绝对值 > 8 格 → 退回 `teleport`（相对移动 8 格上限）。
  - 位移 NaN/Infinity → 退回原地 `teleport`（否则 NaN 污染客户端跟踪位置，假玩家冻结）。
- **传送**：`ClientboundTeleportEntityPacket` + `ClientboundRotateHeadPacket`。
- **原地转向**：`ClientboundMoveEntityPacket`（Rot）+ `ClientboundRotateHeadPacket`。

周期 2 tick（`ServerTickEndEvent` 里 `(tickCounter & 1) != 0` 跳过奇数 tick，对应原 `BossRenderer.TickEndSyncListener`）。读 `getBody().getLocation()` 与内部"上次发包位置"做差。

### 5.5 动画

- 挥手：`ClientboundAnimatePacket`，SWING_MAIN_ARM。
- 受击：`ClientboundAnimatePacket`，HURT。

### 5.6 移除（remove）

- `ClientboundRemoveEntitiesPacket`（移除实体）
- `ClientboundPlayerInfoRemovePacket`（移除玩家列表，传 uuid）

### 5.7 物理本体（隐形盔甲架）

生成参数照抄 `ModelBoss` 构造器里的 `world.spawn(loc, ArmorStand.class, a -> {...})`：`invisible + silent + small=false + marker=false(必须有命中盒) + basePlate=false + arms=false + gravity=true + invulnerable=false + persistent + removeWhenFarAway=false`，血量属性设 1024 缓冲、`SCALE` 属性设 1.4（放大命中盒，严格包含玩家模型 → 射线优先命中盔甲架）。

### 5.8 追击寻路（setVelocity + 绕墙/跳跃）

照抄 `ModelBoss.chase()`（已含简单避障，勿用完整 A*）：
- 每 tick 朝 `target` 水平 `setVelocity`（`CHASE_SPEED=0.15`），贴到 `CHASE_STOP_DIST=2.2` 停。
- 水平速度 `>= KNOCKBACK_SPEED_THRESHOLD=0.08` 时判定正在被击退，不覆盖。
- **卡住检测**：记录上一 tick 位置，贴地连续 4 tick 位移 < 0.02 格判定被方块挡住。
- **沿墙滑动**：卡住时从目标方向按 `[0, ±45, ±90, ±135, 180]` 度试探，取第一个脚部+头顶都不被实心方块挡的方向。
- **跳跃翻越**：被围死或正前方只有 1 格台阶（脚部挡、头顶空）时贴地跳（`JUMP_VELOCITY=0.5`，8 tick 冷却）。

### 5.9 受伤结算（两条路径统一到 FakePlayer 内部血量）

照抄 `ModelBoss.applyDamage()` + `RealEntityDamageListener`（纯 Bukkit API，无需反射）：

1. **盔甲架命中盒（主路径）**：`EntityDamageByEntityEvent`（近战/弓箭/爆炸/火焰）→ 解析攻击者（Player 直击 / Projectile 的 shooter）→ 转血量。保留原版击退，近战（Player 直击）手动 `setVelocity` 击退（`safeKnockback`）。
2. **攻击包拦截（兜底）**：见 5.10，命中后回调 `onAttack`，主插件算伤害调 `damage()`。
3. 血量归零 → `alive=false` → 调 `onDeath.accept(killer)`。

`computeDamage` / `isCriticalHit` / `safeKnockback` 等工具也从 `ModelBoss` 迁入（或保留一份在主插件由回调传入，自行决定）。

### 5.10 攻击包拦截（netty 注入，最费劲的部分）

> 这里不是发包，而是**截获玩家→服务端的入站包**，必须往玩家 netty 通道注入处理器。

1. 拿玩家 netty `Channel`：`ServerPlayer.connection`（ServerGamePacketListenerImpl）内部的 `connection` 字段（`net.minecraft.network.Connection`）的 `channel` 字段（`io.netty.channel.Channel`）。反射拿，判空（登录完成前可能 null）。
2. 往 channel pipeline 加 `io.netty.channel.ChannelDuplexHandler`（`channelRead` 拦截入站），记录 handler 引用以便 `remove()` 时卸载。
3. 入站包里找 `net.minecraft.server.network.ServerboundInteractPacket`（1.21.x 交互/攻击共用类，**具体类名对照服务端 jar 核实**），Action 为 ATTACK 且 `entityId == 假玩家 entityId` 时：
   - 从读流程移除该包（不再 `ctx.fireChannelRead`，等价 PacketEvents 的 `setCancelled(true)`），**必须移除，否则服务端找不到实体报错/踢人**。
   - 拿攻击者（从 channel 反查玩家 / `connection.getPlayer()`）。
   - **netty 线程不能直接调 Bukkit 主线程 API**，`Bukkit.getScheduler().runTask(plugin, () -> onAttack.accept(player))` 调度回主线程。
4. 攻击者可能 null/死亡/离线，回调前判空。

> 参考：主插件原 `BossRenderer.FakePlayerHitListener`（拦截 `WrapperPlayClientInteractEntity` ATTACK）。反射版复刻同样"拦截→取消→主线程回调"逻辑，只是换成 netty 注入。

## 6. 主插件侧对接点（改造方向）

主插件改造后（供理解，不要求附属插件改动）：

- **保留**：皮肤获取（`BossSkin` 里的 value+signature 构建）、AI 技能循环（`PlayerBoss.startAI` 的影遁/幻影斩/近战）、掉落与公告（`PlayerBoss.onDeath` / `VillageCaptain.onDeath`）、`BossMenu` 血条追踪。
- **删除/替换**：`ModelBoss`（本体/血量/追击）和 `BossRenderer`（发包/拦截/同步）整体迁入附属插件的 `FakePlayer`。主插件改走 `FakePlayerFactory` 接口。
- **无附属插件兜底**：主插件保留"隐形盔甲架 + 伤害事件"的旧路径（`ModelBoss` 若保留则作为兜底），或直接不渲染（Boss 只有隐形盔甲架）。

> 附属插件只需实现第 3 节接口。主插件与 PE 版代码是否删除由主插件后续决定（不影响附属插件）。

## 7. 环境与约束

- 服务端：**Paper / Purpur 1.21.11**（固定版本，无需跨版本兼容）。
- 运行时 NMS 是 Mojang 映射（见 5.1 类名）。
- `paper-api` 编译期**不含** `net.minecraft.*`、`org.bukkit.craftbukkit.*`、`com.mojang.authlib.*`、`io.netty.*`，附属插件用反射（`Class.forName`）拿这些类，或自行引入 mojang-mapped server 依赖（反射最省构建）。
- `com.google.gson` 由 Paper 运行时提供；`io.netty.*` 是服务端自带依赖（攻击拦截要用）。

## 8. 验收标准

1. 召唤 Boss 后，玩家能看到一个带指定皮肤、穿钻石剑的完整玩家模型。
2. 模型每 2 tick 自动跟随盔甲架位置/旋转；追击时能绕墙、跳 1 格台阶，挥手/受击动画正确。
3. 玩家攻击 Boss：盔甲架命中盒 + 攻击包拦截两条路径都正常扣血/击退，服务端不报错、不踢人。
4. 血量归零触发 onDeath 回调，主插件正常掉落/清血条；模型消失、netty 处理器卸载、无残留。
5. 后加入/换世界的玩家能正确增删模型。
6. 客户端日志**无** `IOException("Packet was larger than I expected")`、无元数据类型不匹配踢人。
7. 皮肤 value 为空时优雅降级（默认皮肤，不报错）。
